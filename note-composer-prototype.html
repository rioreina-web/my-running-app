Typing a note.

The composer moves out of the record button's slot and onto its own sheet. The slot was never the problem to patch — a full-viewport page inside a scroll view cannot win against the keyboard, and the tab bar takes another 50pt off the top of what's left.

Decisions in this draft

What changed, and why.

  1. The composer gets its own sheet.This reverses the call in LOG-WILD-APPLY.md §6d, which put the composer in the record button's slot so “Type a note instead” wouldn't look like a dead button. That reasoning was right about the symptom and the sheet keeps the cure — it opens instantly on tap. But the slot sits at the bottom of a full-viewport page inside a scroll view, which is a fight with the keyboard that cannot be won by adjusting padding.
  2. Linked run stays, compressed to one line.You still need to know where the note lands, and “Change ↗” still opens the picker. It does not need the 32pt figure and the chip rail twice — that block is already doing its job on the screen underneath.
  3. Save is a state, not a button.Grey until the field has non-whitespace, then the one red. It's the same “verb + arrow” pattern as Mark complete ↗ in the design system, so nothing new to learn.
  4. “Record instead ↗” moves to the footer.Still there, still quiet, but out of the writing surface. In the current build it sits under the text field where it competes with the thing you are typing into.
  5. No “Uploading…” in the composer.That status belongs to the voice path. It appears in the lede on the screen behind, which is where a memo upload actually is.
  6. Crimson Pro for the note body.Prose is what the athlete wrote. Italic JetBrains Mono is a transcript — the machine quoting you back. The system separates those two and this is the writing case.
  7. Open question — the date stamp.The footer currently reads Mon · Aug 24. If a note should be attachable to a past day without going through the run picker, that stamp wants to be tappable and this draft does not handle it.
